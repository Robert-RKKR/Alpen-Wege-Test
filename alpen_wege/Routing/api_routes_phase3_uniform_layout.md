# Phase 3: one uniform layout for every resource (delivered 2026-10-24)

This phase changes the file layout decided in `api_routes_implementation_plan.md`. There, a resource could be a single file (size S) or a folder (size L). You asked for **one concept in all apps**, so there is no size S any more. URLs, permissions, schemas and function names did not change.

## The rule

Every resource, in every app, is a **folder** with one file per action. Special kinds of tables get a type folder with the same names as in `models/`:

| Folder | What goes in it |
|---|---|
| `routes/<resource>/` | regular models and features: `country/`, `poi/`, `gear/`, `track/`, `auth/`, `user/`, `access_policy/`, `event_log/`, `settings/`, `my_jobs/`, `jobs/`, `broadcast/`, `celery/`, `ws/` |
| `routes/m2m/<resource>/` | link tables (`poi_region/`) |
| `routes/ref/<resource>/` | reference tables of `core` (19 tables and `resource_type/`) |
| `routes/sub/<resource>/` | sub tables (none have routes yet) |

Inside a resource folder:

| File | Content |
|---|---|
| `_router.py` | the one `APIRouter` of the resource (prefix and Swagger tag). Every endpoint file imports it; FastAPI refuses sub-routers with an empty path, so endpoint files cannot have their own |
| `__init__.py` | imports the endpoint files (fixed paths such as `/upload-csv`, `/stats`, `/me` first) and exports `router` |
| `_shared.py` | helpers used by several endpoint files (only when needed) |
| `get_many.py`, `get_one.py`, `create.py`, `update.py`, `delete.py`, `upload_csv.py` | one endpoint each; special actions get their own name (`rescan`, `geometry`, `restore`, `stats`, `compare`, `activate`, ...) |

A resource folder never contains folders; a type folder contains only resource folders. `tests/test_routes_standard.py` (now 8 tests) enforces this: no loose files in `routes/`, type folders only `m2m`, `ref`, `sub`, every module imported by its `__init__.py`, URL shape, no undefined names, no shadowed routes.

## What the current code looks like now

```
compendium/routes/   country/ region/ poi/ card/ post/            m2m/poi_region/
core/routes/         ref/ company/ gear_type/ rarity/ ... (19)    ref/resource_type/
explorer/routes/     gear/ track/
profile/routes/      auth/ user/ access_policy/
management/routes/   event_log/ settings/ my_jobs/ jobs/ broadcast/ celery/ ws/
```

`post/` is the Post model (editorial posts), not the HTTP method. The 19 reference tables are no longer generated by one factory function: each has its own folder with the real code in every file, like every other model. Their function names stay `list_items`, `create_item`, ... so the Swagger texts and operation ids are unchanged. The price: the same code exists 19 times; a change to all reference tables needs 19 edits.
